# Чистка нейрослопа

Нейрослоп — типовой «усреднённый» вид, по которому сразу видно, что картинку или интерфейс сделала нейросеть. Задача: найти признаки, сказать, что убрать (или что уже убрано), и вычистить — правкой файла, готовым промптом для генератора, правкой стилей или ручной доработкой.

Когда применять: просят проверить или почистить картинку, концепт интерфейса, игровой экран, постер, иллюстрацию, сайт, лендинг, веб- или мобильное приложение от нейросети («навайбкоженный» сайт, сайт из v0/Lovable/Cursor); «выглядит как нейрослоп», «как у всех», «жёлтое», «дёшево»; просят промпт, чтобы переделать картинку; присылают результат перегенерации на проверку; самопроверка перед показом сгенерированного концепта.

Порядок: что передо мной → замер → осмотр → отчёт → **готовые промпты** → проверка результата.

## 0. Скрипт замера

Для сайтов и приложений есть второй скрипт, `scripts/webslop.py` (раздел 3а). Если рядом с этим файлом есть `scripts/cast.py` — используй его. Иначе один раз за сессию сохрани скрипт ниже в рабочую папку (scratchpad) как `cast.py`. Запуск: `python3 -I cast.py …`. Нужны pillow и numpy (`pip install pillow numpy --break-system-packages`, если нет).

```python
#!/usr/bin/env python3
"""Замер и правка цветового сдвига (жёлтый «фильтр», сепия, розовый/зелёный, синий) у картинок.

  python3 cast.py measure a.png b.jpg ...                b* и a* светлых мест (фон, бумага) и всего кадра
  python3 cast.py fix in.png out.png [--target 0] [--a]  сдвинуть b* светлых мест к target
                                                         (0 — нейтрально, 5–7 — лёгкая сепия);
                                                         --a — заодно убрать розовый/зелёный (a* к 0)
  python3 cast.py sheet out.jpg a.png b.png ...          контактный лист для серии (без ImageMagick)
Шкала b*: |b*| ≤ 3 нейтрально; +4…+8 тёплый сдвиг; > +8 явная желтизна; < −3 холодный (синий) сдвиг.
|a*| > 4 — розовый (+) или зелёный (−) сдвиг. Нужно: pip install pillow numpy.
"""
import argparse
import io
import sys
import numpy as np
from PIL import Image, ImageCms

SRGB = ImageCms.createProfile('sRGB')
RGB2LAB = ImageCms.buildTransformFromOpenProfiles(SRGB, ImageCms.createProfile('LAB'), 'RGB', 'LAB')
LAB2RGB = ImageCms.buildTransformFromOpenProfiles(ImageCms.createProfile('LAB'), SRGB, 'LAB', 'RGB')
MIN_LIGHT = 0.03  # меньше 3% светлых пикселей — замер по «светлому» ненадёжен


def load(path):
    """RGB в sRGB (с учётом встроенного профиля, напр. Display P3 со скриншотов) + альфа, если есть."""
    im = Image.open(path)
    alpha = im.getchannel('A') if 'A' in im.getbands() else (im.convert('RGBA').getchannel('A') if im.mode == 'P' and 'transparency' in im.info else None)
    rgb = im.convert('RGB')
    icc = im.info.get('icc_profile')
    if icc:
        try:
            rgb = ImageCms.profileToProfile(rgb, ImageCms.ImageCmsProfile(io.BytesIO(icc)), SRGB, outputMode='RGB')
        except Exception:
            pass
    return rgb, alpha


def lab(im):
    return [np.asarray(c, dtype=float) for c in ImageCms.applyTransform(im, RGB2LAB).split()]


def verdict(b, a):
    if np.isnan(b):
        return 'светлых мест нет — замер не применим'
    v = ('нейтрально' if abs(b) <= 3 else 'тёплый сдвиг' if b <= 8 else 'явная желтизна') if b >= -3 else 'холодный (синий) сдвиг'
    if abs(a) > 4:
        v += ', розовый сдвиг' if a > 0 else ', зелёный сдвиг'
    return v


def stats(im, alpha=None):
    L, a, b = lab(im)
    light = L * 100 / 255 > 85
    if alpha is not None:
        light &= np.asarray(alpha) > 0  # прозрачное не считаем
    bl = (b - 128)[light].mean() if light.any() else float('nan')
    al = (a - 128)[light].mean() if light.any() else float('nan')
    return L, a, b, light, bl, al


def measure(path):
    im, alpha = load(path)
    small = im.copy(); small.thumbnail((800, 800))
    sa = alpha.resize(small.size) if alpha is not None else None
    _, _, b, light, bl, al = stats(small, sa)
    note = '' if light.mean() >= MIN_LIGHT or np.isnan(bl) else '  ⚠ мало светлых мест (тёмная сцена или UI): смотри «b* кадра», «лечить» не нужно'
    print(f'{path}: b* светлого {bl:5.1f}  a* светлого {al:5.1f}  b* кадра {(b - 128).mean():5.1f}  '
          f'светлого {light.mean():4.0%}  → {verdict(bl, al)}{note}')


def fix(src, out, target, fix_a):
    im, alpha = load(src)
    L, a, b, light, bl, al = stats(im, alpha)
    if light.mean() < MIN_LIGHT:
        sys.exit(f'{src}: светлых мест {light.mean():.0%} — это тёмная сцена или UI, автоправка оттенка её испортит. Не правлю.')
    w = L / 255  # тёмное почти не трогаем, светлое — сильнее
    b = np.clip(b - (bl - target) * w, 0, 255)
    if fix_a:
        a = np.clip(a - al * w, 0, 255)
    res = Image.merge('LAB', [Image.fromarray(np.round(x).astype('uint8')) for x in (L, a, b)])
    res = ImageCms.applyTransform(res, LAB2RGB)
    if alpha is not None:
        res.putalpha(alpha)
    kw = {'quality': 95, 'subsampling': 0} if out.lower().endswith(('.jpg', '.jpeg')) else {}
    if alpha is not None and out.lower().endswith(('.jpg', '.jpeg')):
        res = res.convert('RGB')
        print('⚠ JPEG не хранит прозрачность — сохраняй в PNG/WebP, если она нужна')
    res.save(out, **kw)
    print(f'{src} → {out}: сдвиг b* на {target - bl:+.1f}' + (f', a* на {-al:+.1f}' if fix_a else ''))
    measure(out)


def sheet(out, files, cols=2, width=1000):
    ims = []
    for p in files:
        im, _ = load(p)
        ims.append(im.resize((width, round(im.height * width / im.width))))
    rows = -(-len(ims) // cols)
    h = max(i.height for i in ims)
    canvas = Image.new('RGB', (cols * width, rows * h), (128, 128, 128))  # нейтрально-серый, не влияет на оценку цвета
    for k, im in enumerate(ims):
        canvas.paste(im, ((k % cols) * width, (k // cols) * h))
    canvas.save(out, quality=90)
    print(f'{out}: {len(ims)} шт., {cols} в ряд')


if __name__ == '__main__':
    ap = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    sub = ap.add_subparsers(dest='cmd', required=True)
    m = sub.add_parser('measure'); m.add_argument('files', nargs='+')
    f = sub.add_parser('fix'); f.add_argument('src'); f.add_argument('out')
    f.add_argument('--target', type=float, default=0); f.add_argument('--a', action='store_true')
    s = sub.add_parser('sheet'); s.add_argument('out'); s.add_argument('files', nargs='+'); s.add_argument('--cols', type=int, default=2)
    args = ap.parse_args()
    if args.cmd == 'measure':
        for p in args.files:
            measure(p)
    elif args.cmd == 'fix':
        fix(args.src, args.out, args.target, args.a)
    else:
        sheet(args.out, args.files, args.cols)
```

## 1. Что передо мной

От этого зависит, чем чистить:

- **Сгенерированная картинка** (концепт, арт, «скриншот» от нейросети): лица и мелкие детали при увеличении «плывут», объекты повторяются копипастой, все рамки нарисованы по-разному. Чистим промптом (раздел 5) или правкой файла.
- **Настоящий отрисованный интерфейс** (скриншот приложения, игры, сайта): текст чёткий, цифры живые. Промпт тут бессмыслен — чистим дизайн и стили (раздел 6).
- **Смесь**: интерфейс поверх сгенерированного арта. Оцениваем слои отдельно.
- **Сайт или веб-приложение** (ссылка, html, код проекта) и **мобильное приложение** — отдельный раздел 3а: там свой инструмент (`webslop.py`) и свои признаки.

Запиши размер картинки (`python3 -I -c "from PIL import Image; print(Image.open('x.png').size)"`) — он понадобится, чтобы задать формат в промпте и поймать смену формата после генерации.

## 2. Замер оттенка (до того как смотреть глазами)

Жёлтый «фильтр» — самый частый признак: модели «утепляют» картинку, если баланс белого не задан, а слова warm / cream / vintage / cinematic его усиливают.

```bash
python3 -I cast.py measure img1.png img2.jpg   # b* и a* светлых мест (фон, бумага) и всего кадра
```

- |b*| ≤ 3 — нейтрально; +4…+8 — тёплый сдвиг; > +8 — явная желтизна; < −3 — холодный (синий). |a*| > 4 — розовый или зелёный сдвиг.
- Меряем только то, что должно быть белым, серым или бумагой. Ночные, тёмные и нарочно тёплые или холодные сцены не «лечим»: для тёмной sci-fi темы синий сдвиг — норма.
- Если светлых мест меньше 3% (тёмный UI, ночь), скрипт предупредит: «светлое» тогда — только текст или огни, замер справочный. Смотри «b* кадра» и глаза. Но b* огней/золота полезно сравнивать между версиями: рост = картинка снова «засветилась».
- Если на картинке интерфейс поверх арта — меряй их отдельно (вырежи полосу UI и фон).

## 3. Осмотр по признакам

Открой картинку и посмотри сам; мелкие места (иконки, подписи, лица, детали арта) увеличь кропом в 2–3 раза. Для серии сначала склей контактный лист (`python3 -I cast.py sheet sheet.jpg a.png b.png c.png`).

| группа | признаки |
|---|---|
| Цвет | бежевый/кремовый фон «по умолчанию»; жёлтый/горчичный без смысла; все цвета на полной насыщенности поровну («салат»); фиолетово-синие градиенты; неон и свечение на тёмном; один акцентный цвет на десяти ролях сразу |
| Тон и свет | тёплый «киношный» оттенок, оранжево-бирюзовая тонировка, сепия, «состаренная» бумага, винтажное зерно, мягкое пятно света за контентом, «светится всё одинаково» |
| Края | толстая чёрная обводка у каждой кнопки и карточки + жёсткая тень-сдвиг (край задан дважды); тонкая рамка + широкая мягкая тень; рамки у всего подряд (карточка, иконка внутри, кнопка); огромные радиусы; цветная полоса сбоку или сверху карточки |
| Композиция | всё по центру и симметрично; одинаковые отступы везде; всё одного веса, нет главного (модальное окно на ярком фоне; в магазине не выделен лучший вариант); карточки в карточках; одинаковые сетки «иконка-заголовок-текст» |
| Перебор декора | статуи, грифоны, гаргульи, филигрань, знамёна на каждой панели и в каждом углу; декоративные фигурки между кнопками и в панелях без функции |
| Повтор | одна и та же иконка на всех карточках, хотя содержимое растёт; объекты-клоны (одинаковые мосты, окна, причалы, деревья); при увеличении детали «тают» в кашу |
| Мусорные значки | «?», «1», «NEW», бейджи и счётчики, которые ничего не значат или дублируют друг друга; подпись внутри иконки, повторяющая заголовок; ресурсы без подписей |
| Шрифт | капс и жирный узкий везде; плоская иерархия; 4–5 случайных шрифтов; Inter/Geist по умолчанию; курсивная антиква «для журнальности»; пилюли-бейджи над заголовками |
| Иллюстрация | клипарт (стоковое здание с вывеской, иконки-машины); звёздочки и спирали над головой, взрывы «БУМ», искорки ✦ +, конфетти; смесь плоского вектора и 3D (линейные иконки рядом с объёмной пачкой денег); мультяшная вставка в реалистичном экране; типовые лица (седой маг, девушка в капюшоне, «злой полицейский»); арт не показывает то, что подписано («обитель стихий» без стихий); грань персонажа вылезает за рамку |
| Текст | опечатки и псевдослова; **подмена кириллических букв** (н→п, н→л, е→є/6, я→н: «Нужпо», «Камель», «В казпе») — читай каждое слово по буквам; английский там, где нужен русский; утёкший текст промпта («UI-kit spec 16:9», «Professional…»); номера и кавычки в подписях разделов; выдуманные строки; дефис или «минус с пробелом» вместо − (− 9% → −9%); тавтологии («Казна» в колонке «В казне») |
| Цифры | проверь арифметику: скидки против зачёркнутых цен, «было − нужно = останется», проценты, «33/110» против полоски. Нейросети рисуют числа, которые не сходятся |
| Состояния | вид противоречит тексту: «Покупка недоступна» под активной кнопкой; условие («Нужен опыт: 100») без текущего значения; нет активного пункта в навигации; два показателя в одной ячейке без понятной связи |
| Порядок | один и тот же список в разном порядке на одном экране (ресурсы в панели и в таблице); похожие иконки для разного (камень = серебряный слиток рядом с металлом) |
| Подача | телефоны в рамке с чёлкой на бежевом фоне; фальшивая строка состояния; «презентационный» стол с тенью |
| Смысл | персонаж случайно похож на реальное лицо; символика, которую не заказывали; название или логотип совпадают с известным брендом, альбомом, фильмом, игрой (риск по товарному знаку — сказать «проверь», не утверждать); реальное место с выдуманной географией |

**Вкус пользователя главнее списка.** Если ему нравится приём из списка (старая бумага, лёгкая сепия, объём у заголовка, скошенные углы как фирменный приём), не выкидывай, а приглуши и запиши как исключение. Не перечищай: «стерильно» — тоже провал. Жанровые приёмы (sci-fi скосы, готика у тёмного фэнтези) — не слоп сами по себе; слоп — когда их навалено на всё подряд.

## 3а. Сайты, веб-приложения и мобильные приложения

Визуальные признаки из раздела 3 действуют и здесь, но у сайтов есть свой узнаваемый набор: модели собирают «среднее» из обучающего кода — дефолты Tailwind UI (indigo-500 был просто нейтральной заглушкой для демо), стартовые шаблоны, shadcn без настройки.

### Как проверять

Инструмент — `scripts/webslop.py` (рядом с этим файлом; если его нет — скачай: `https://raw.githubusercontent.com/Bloodrabbid/neuroslop-cleaner/main/scripts/webslop.py`). Нужен Playwright с Chromium.

```bash
python3 -I webslop.py audit https://site.ru --out shots        # или локальный .html; --dark для тёмной темы
python3 -I webslop.py scan ./src                               # поиск по исходникам проекта
```

- `audit` снимает страницу целиком на 390, 768 и 1440 px, ищет горизонтальный скролл (и виновные элементы), меряет зоны нажатия на телефоне, считает визуальные паттерны по вычисленным стилям и даёт полосу: **CLEAN** 0–1, **MILD** 2–3, **SLOPPY** 4–6, **TERMINAL** 7+. Плюс штампы в видимом тексте.
- `scan` ищет в коде дефолты Tailwind/shadcn, стекло, анимации на всём, заглушки, штампы. Совпадение в коде вторично: неиспользуемый код тоже находится — сверяй с `audit`.
- Скрипт — первый проход. **Потом обязательно открой скриншоты глазами**, особенно мобильный: композицию, иерархию и смысл скрипт не видит.
- Страница за логином — попроси скриншоты или пройди через браузер пользователя. Нативное приложение — только по скриншотам с телефона, скрипт не применим.

### Признаки

| группа | признаки |
|---|---|
| Шаблон страницы | центрированный первый экран на градиенте или размытых «пятнах»; пилюля «✨ Новое: …» над заголовком; одно слово заголовка градиентом; подзаголовок пересказывает заголовок; две кнопки «Начать бесплатно» + «Подробнее»; строка логотипов; строка метрик «10K+ / 99.9% / 24/7»; три одинаковые карточки «иконка в цветном квадрате → заголовок → строка»; отзывы «— Анна, CEO»; плашка «Готовы начать?»; пары «Наши возможности» → «Вот наши возможности» |
| Цвет | indigo/violet как акцент, `from-purple-500 to-blue-500`, циан и неон на почти чёрном, аура-свечение за героем, 5–6 насыщенных цветов без иерархии |
| Поверхности | `rounded-2xl` + `shadow-lg` на всём, стекло `backdrop-blur`, карточки в карточках, всё обёрнуто в карточки, цветная полоса слева у блоков |
| Шрифт | Inter/Geist/system и для текста, и для заголовков; моноширинный «для технологичности» вне кода; капс-надзаголовки с разрядкой |
| Иконки | эмодзи как иконки, пункты меню и маркеры; один набор тонких линейных иконок на всё подряд; бессмысленные цветные точки-статусы |
| Движение | fade-up на каждом блоке, пружинящий easing, счётчики-«накрутки» цифр, `transition-all` |
| Текст | штампы: «раскройте потенциал», «откройте новые возможности», «на новый уровень», «бесшовный», «инновационный», «уникальный», «мощный инструмент», «всё в одном», «интуитивно понятный», «не просто X, а Y», «попрощайтесь с…»; англ.: unlock, seamless, elevate, empower, supercharge, effortless, cutting-edge, game-changer, «Build faster. Ship smarter.»; выдуманные метрики и отзывы; кнопки «Get started/Learn more/Подробнее» везде; тройки в каждом перечислении. Длинное тире — признак только в английском тексте: в русском это нормальная пунктуация |
| Адаптив | горизонтальный скролл на телефоне (таблица цен или блок фиксированной ширины); функции спрятаны на мобильном; зоны нажатия меньше 24 px (провал WCAG 2.2 AA) или меньше 44 px (ниже Apple 44 pt / Material 48 dp; ссылки внутри абзаца — исключение) |
| Состояния | нарисован только «идеальный» экран: нет пустого, загрузки, ошибки, hover/focus; все кнопки одинаково главные; модальные окна на всё |
| Вторая волна | то, что модели выдают, когда первую волну запретили: кремовый фон около `#F4F1EA` + антиква + терракота около `#D97757`; почти чёрный с одним кислотным акцентом; «газетная» вёрстка — тонкие линейки, нулевые радиусы; капс-надзаголовки, моно-подписи, стрелка → на каждой ссылке, одно слово заголовка курсивом или цветом, нумерация 01/02/03. Это не «чисто», а следующий шаблон |

Здравый смысл: карточки уместны в дашбордах и лентах, центрирование — на коротком лендинге, тёмная тема — как осознанный выбор. Слоп — не приём, а приём по умолчанию, без связи с продуктом. Главный вопрос: это решение человека или дефолт модели?

### Мобильные приложения (нативные)

- **Норма, не слоп:** системный шрифт (SF Pro, Roboto), стандартная панель вкладок, навигационный стек, шиты, системные переключатели. Не записывай их в «типовое».
- **Слоп — веб-вид внутри приложения:** веб-шрифт вместо системного, свои кнопки и переключатели вместо системных, линейные иконки вместо SF Symbols / Material Symbols, карточки с тенью «как на сайте», нет Dynamic Type, нет тактильного отклика, переходы не как в системе.
- **Числа:** зоны нажатия ≥ 44×44 pt (iOS) и ≥ 48×48 dp (Android); контент не заходит под «чёлку», вырез камеры и домашний индикатор; на макетах — без фальшивой строки состояния.
- Ощущение «родного» приложения проверяется на устройстве, а не по скриншоту — скажи об этом пользователю.

### Чистка сайта или приложения

1. **Правки в коде** — конкретными значениями: палитра из 4–6 цветов с ролями (токены), 1–2 шрифта со шкалой размеров, радиусы и тени по иерархии (или линии вместо теней), одна главная кнопка + текстовая ссылка, выравнивание по левому краю, настоящий экран продукта вместо метрик, тексты языком клиента, мобильная вёрстка без скролла вбок, зоны нажатия ≥ 44 px. Предложи сохранить направление в `DESIGN.md`, чтобы все страницы брали одни токены.
2. **Промпт для генератора кода** (Claude, v0, Lovable, Cursor, Bolt) — шаблон В:

```
Design direction for [продукт — для кого и зачем, одной фразой]:
- Palette: [4–6 hex с ролями: фон, текст, приглушённый текст, линии, акцент только для главного действия, предупреждение]. No purple, indigo, violet or cyan unless listed. No pure #000/#fff.
- Type: headings [шрифт], body [шрифт], scale [напр. 48/32/17/15]. Not Inter, Geist or system-ui for both.
- Layout: left-aligned. First screen: [конкретный элемент продукта, напр. реальный экран приложения]. No centered hero formula, no pill badge, no logo row, no stats row, no three identical icon cards, no testimonials unless real quotes are given below.
- Surfaces: radius [6px]; thin lines instead of shadows; cards only for independently actionable items. No glassmorphism, no glow, no gradient text, no emoji as icons.
- Copy, use exactly: [тексты]. Buttons say what they do. No invented numbers. Avoid: unlock, seamless, elevate, empower, supercharge, effortless, cutting-edge.
- Motion: none, except [одно осмысленное].
- Responsive: no horizontal scroll at 390px, all tap targets at least 44px, same features on mobile.
- States: design empty, loading, error, hover and focus states.
```

   После генерации — снова `webslop.py audit` и осмотр скриншотов, отчёт «было → стало» (раздел 7). Следи, чтобы вместо первой волны не пришла вторая.

3. **Примеры «до / после»** — в репозитории скилла, папка `examples/`: лендинг (`examples/web`) и игровой экран с тремя проходами через генератор (`examples/game`).

## 4. Отчёт

Коротко, таблицей, самое заметное сверху:

| признак | где | что сделать |
|---|---|---|
| жёлтый оттенок, b* 12 | фон всех экранов | нейтральный баланс белого, фон #FFFFFF (или лёгкая сепия b* ≈ 6, если её хотят) |
| тень-сдвиг + обводка | кнопки | плоская заливка, радиус 6 px |

Дальше:
- **«Уже чисто: …»** — что в порядке (честно, без похвалы ради похвалы).
- **«Не про слоп, но важно»** — противоречивые состояния, несходящиеся цифры, тавтологии, порядок, риск по названиям. Это часто важнее косметики.
- **Готовые промпты** (раздел 5) — для сгенерированных картинок давай их сразу, не дожидаясь просьбы. Для настоящего интерфейса — конкретные правки стилей (раздел 6).

## 5. Готовые промпты для генератора

Всегда давай два варианта, в блоках кода, на английском (генераторы надёжнее понимают инструкции на английском), с точными русскими строками:

- **А. Правка** — прикрепить исходник, изменить только перечисленное. Хорошо, когда раскладка удачная и правок до ~8.
- **Б. С нуля** — полное описание экрана без исходника. Когда правок много, основа сама насквозь слоп или правка уже дала регрессии. Если пользователь хочет сохранить раскладку исходника — вариант **Б′. С нуля по референсу**: исходник прикрепляется как референс раскладки, но всё описывается заново, а то, что из исходника брать нельзя, запрещается явно.

Коротко скажи, какой рекомендуешь и почему.

### Правила для обоих вариантов

- **Формат.** Укажи соотношение и размер исходника в промпте («16:9, 1280x720») и скажи пользователю выставить формат в настройках (Google AI Studio → Aspect ratio; в Gemini-приложении промпт про формат часто игнорируется и выходит квадрат).
- **Текст.** Каждая надпись — дословно, без кавычек в тексте промпта (иначе нарисует кавычки). Добавь: «Render all Cyrillic text exactly as written, no quotation marks, no extra text».
- **Числа.** Перечисли все числа, которые должны остаться, — генератор их «плавит».
- **Списки** (ресурсы, пункты меню) — в одном порядке во всех местах экрана, перечисли явно «left to right».
- **Количество** декора — точно: «exactly two statues, one at each top corner. No other statues». Иначе вернётся.
- **Стиль вставок** — «same painterly style as the rest of the screen, not cartoon, not casual mobile game style».
- **Персонажи** — конкретно: возраст, лицо, одежда; при апгрейде — «the SAME person», иначе выйдет другой типовой персонаж. Аура/эффекты — «fully inside the frame».
- **Реальные места** — называй ключевые объекты и их различия, иначе будут клоны.
- **Ночь и тёмные сцены** — «neutral dusk lighting, no orange-teal grading», доля света («only about 30% of windows lit»).
- **Активные состояния** — что выделено и чем («Замок is active, highlighted with a muted gold frame»).
- **Слова-триггеры** не используй: warm, cozy, cream, beige, vintage, retro, aged, cinematic, golden hour, stunning, professional, epic, glowing, «как в Figma».
- **Цвет** — по значимости, с hex и ролями: «80% экрана — нейтральные; один смысловой цвет на экран; акцент X — только для Y».
- **Блок AVOID** в конце: свечение, блики, искорки, лишний декор, лишний текст, смена чисел, мультяшный стиль — плюс всё конкретное, что было слопом на исходнике.

Для светлых интерфейсов, сайтов и постеров в начало промпта добавляй общий анти-слоп блок:

```
Avoid the typical AI-generated look: neutral white balance (daylight 6500K), no warm or sepia cast, no aged paper.
No offset drop shadows and no thick black outlines on buttons or cards; flat fills, 6px corners.
Left-aligned text on a 4-column grid, one dominant element per screen, related items grouped tight.
No sparkles, stars around heads, spirals, explosion bursts, confetti, clip-art buildings, emoji, gradients or glow.
No device frames, notches or fake status bars. Few words, exactly as given.
```

Если пользователь хочет фактуру или сепию — замени первую строку на точное описание («very light paper with a little sepia, b* about 6, faint grain, sparse pen stipple dots instead of shadows»). Для ночной или тёмной сцены — «neutral dusk lighting, no orange-teal grading, lights warm but sparse»; строки про сетку и радиусы для жанровых игровых экранов убери.

### Шаблон А — правка

```
Edit this [game UI screenshot / illustration]. Output aspect ratio [16:9, 1280x720], do not crop. Keep the overall layout, positions, color palette ([...]) and ALL text and numbers exactly as they are, except for the changes listed below. Render Cyrillic exactly as written, do not render quotation marks.

[ГРУППА, напр. BACKGROUND]
1. [одна конкретная правка: что, где, на что]
2. ...
[ГРУППА: DECOR / ILLUSTRATION / ICONS / TEXT CHANGES]
...

Avoid: [glow, lens flares, sparkles, ...], new text or labels that are not listed here. Keep these numbers unchanged: [...].
```

Правки нумеруй и группируй по зонам экрана. Больше ~10 пунктов — сразу предложи разбить на два прохода (сначала фон и декор, потом текст и иконки).

### Шаблон Б — с нуля (Б′ — по референсу)

```
[Б′: Use the attached screenshot as a reference for layout, composition and palette only. Generate a NEW clean version. Do not copy its ornaments, characters or decorations; follow only the description below.]
[Тип экрана и жанр], [16:9, 1280x720]. [Стиль], [палитра], [свет]. Render all Cyrillic text exactly as written, no quotation marks, no extra text.

BACKGROUND
[что на фоне, насколько затемнён]

[ЗОНА 1, напр. TOP BAR] ([как выглядит: simple dark strip, no ornaments])
[содержимое слева → справа, с точными строками и числами]

[ЗОНА 2 ... ЗОНА N — сверху вниз, слева направо; таблицы построчно: icon, name, numbers]

ICONS
[иконки, которые путаются: как именно выглядят и чем отличаются]

AVOID
[общий список + конкретный слоп исходника]
```

Описывай экран зонами сверху вниз, таблицы построчно. В Б′ отдельно запрещай то, что на исходнике было не так (референс «протекает»: старые персонажи и декор возвращаются, если их не запретить словами).

### Текстовые экраны: подложка без текста

Если на экране много мелкого текста и цифр (таблицы, магазины, диалоги), предложи надёжный путь: сгенерировать **подложку без текста** («all text areas left empty, no letters, no numbers») и наложить настоящий текст шрифтом в Figma или движке. Генераторы портят кириллицу даже при идеальном промпте.

## 6. Чистка без генератора

Выбирай самый дешёвый способ, который закрывает находку.

1. **Правка файла** — оттенок, кадрирование рамки телефона:

```bash
python3 -I cast.py fix in.png out.png              # к нейтральному
python3 -I cast.py fix in.png out.png --target 6   # оставить лёгкую сепию
python3 -I cast.py fix in.png out.png --a          # заодно убрать розовый/зелёный
```

   Скрипт сам откажется править тёмную сцену или UI (светлых мест < 3%) — такие кадры правят промптом или стилями. Прозрачность сохраняется в PNG/WebP; в JPEG она теряется — скрипт предупредит.

2. **Вёрстка и интерфейс в коде** (HTML/CSS, игровой UI): ищи те же признаки в стилях — `box-shadow` со сдвигом без размытия + `border` у всех кнопок, `border` у всех вложенных блоков сразу, `border-radius` ≥ 20px везде, фон `#f5f0e6`-подобный без замысла, градиенты и `radial-gradient`-пятна в каждой карточке, `text-transform: uppercase` на всём, один шрифт без иерархии, цветная полоса `inset 4px 0 0` сбоку карточки, glow через `box-shadow 0 0 Npx цвет`. Предлагай конкретную замену значений. Если стилей не дали — оцени по скриншоту и попроси CSS. Шрифт, которого нет в природе, подбери из настоящих — с кириллицей и свободной лицензией.

3. **Отдельный ассет + ручная сборка** — когда один элемент генератор упорно не чинит (иконка, иллюстрация) или каждая правка всего экрана ломает уже готовое. Дай промпт на один ассет «isolated on a plain flat dark background, centered» и скажи собрать экран в Figma/Photoshop из удачных кусков разных версий.

## 7. Проверка результата («было → стало»)

Когда пользователь присылает перегенерацию:

1. Размер: совпадает ли формат с исходником (частая поломка — квадрат вместо 16:9).
2. `cast.py measure` старой и новой версии рядом.
3. Кропы мест, которые правили, и всего текста — читать **по буквам**; числа сверить с исходником.
4. Отчёт тремя группами:
   - ✅ **исправлено**;
   - ❌ **не исправлено** — что генератор проигнорировал;
   - ⚠️ **регрессии** — что было хорошо и сломалось (вернувшийся декор, пропавшие подписи, потерянное активное состояние, неровные отступы, опечатки, сменившийся персонаж).
5. Следующий шаг — короткий промпт только на оставшееся (шаблон А).

**Правило остановки.** Если элемент проигнорирован два прохода подряд — не проси третий раз, переводи в отдельный ассет. Если за проход регрессий больше, чем исправлений, — перестань гонять весь экран: возьми лучшую версию за основу, остальное — ассетами и руками (раздел 6.3), либо один чистый прогон с нуля (шаблон Б).

## 8. Чего не делать

- Не выкидывай то, что пользователь отметил как нравящееся, — приглуши.
- Не перегенерируй всю серию ради одной находки; перегенерация — одна картинка за раз, если не просили больше.
- Не предлагай промпт для настоящего скриншота интерфейса — правь дизайн.
- Не прогоняй `fix` по тёмным и ночным сценам.
- Не утверждай «чисто», не посмотрев картинку, не замерив оттенок и не прочитав текст по буквам.
- Не считай русское длинное тире признаком нейросети — это обычная пунктуация.
- Не записывай в слоп системные компоненты нативного приложения (SF Pro, Roboto, стандартные вкладки и шиты).
- Не выдавай «вторую волну» (кремовый фон + антиква + терракота, газетные линейки, капс-надзаголовки) за чистый результат.
- Не верь одному скрипту: CLEAN у `webslop.py` не значит «хороший дизайн» — смотри скриншоты.
